**Folder: Clip_02**

First, you’ll start with the most important knowledge in this entire roadmap: the JavaScript language.

JavaScript is one of the most widely used programming languages today. Many famous technologies like React, Angular, NodeJS,… are all built on JavaScript.

Not only that, JavaScript syntax is very beginner-friendly, making it a great choice for newcomers.

However, you don’t learn JavaScript just because it’s popular, but because through JavaScript you will build a solid foundation and strong logical thinking in the early stage.

Remember this: foundational knowledge and logical thinking are extremely important for a professional programmer. In fact, they are far more important than how many new technologies you know.

Once you have mastered JavaScript, learning the remaining knowledge in this roadmap will become much easier.

So in practice, what do people use JavaScript for?

For example, when you’re reading an article with thousands of comments, the website initially shows only the first 20 comments.

When you scroll to the bottom, the site loads and displays the next 20 comments, and this process continues like that.

To implement this feature, JavaScript is used to detect whether you have scrolled near the bottom of the page.

If yes, JavaScript quickly asks the server to send more data for the next 20 comments.

After receiving data from the server, JavaScript displays it on the interface so you can see it. This entire process happens seamlessly, without reloading the page.

Thanks to JavaScript, you can turn a regular static webpage into a fully functional application.

**Folder: Clip_03**

Before we move to the next knowledge area, there is one extremely important thing I need to tell you.

Otherwise, even if you finish the whole roadmap, if your learning method is wrong, your final result still goes back to zero.

What I want to talk about is how to use AI during the learning stage.

When working, you will definitely use AI regularly to improve productivity. However, during learning, you should limit AI usage as much as possible.

You must absolutely not use AI to suggest solutions when doing exercises. The solution must come from your own thinking.

And you should only use AI to remind you of syntax you’ve already learned when you forget it.

I have an example to make this clearer.

Suppose you are doing an exercise that asks you to **find even numbers in an array.**

It’s a mistake if you don’t spend time thinking and immediately rush to ask AI: “Solve this exercise for me.”

Then you look at AI-generated code, copy it in, and run the program.

You might think: “I can read and understand AI’s code, so what’s the problem?”—and falsely assume you now have that problem-solving skill.

But in reality, everything is still zero. Because you have lost the most valuable opportunity: to think for yourself and train your logical thinking.

Knowledge is still outside of you; it isn’t truly yours unless you can do it yourself.

If you can’t solve such a basic problem on your own, how will you analyze and handle complex problems later at work?

Instead, **pause** and don’t rush to write code. Build the habit of reasoning on your own and drafting your solution first.

For example, you can reason like this:

- “Ah, an even number is divisible by 2. So I need to use the % operator to get the remainder. If the remainder is 0, it’s even; otherwise, it’s odd.”
- “Then, to check each number, I need to use a loop to iterate through every element in the array.”
- “Inside each loop, I’ll check whether the current element is divisible by 2.”
- “If it is divisible by 2, I’ll display the value on screen so it’s easier to see.”
After you have your draft solution, then you convert that draft into real lines of code.

While writing code, if you forget the `for` loop syntax, you can use AI to remind you of the `for` loop syntax.

Once you remember it, continue finishing your code.

This is the RIGHT way to learn, helping you train logical thinking and avoid dependence on AI.

In short, reason out the solution yourself, and only ask AI when you forget syntax.

This may take time, and you will write incorrect code many times.

But that is normal. It is exactly through writing wrong code that you learn from experience which knowledge should be applied and which should not, for each specific case.

Gradually, you will build your own experience.

This is not as easy as you think. Sometimes screens that look simple at first glance still require you to **spend a lot of time** to implement exactly according to the design.

**Folder: Clip_08**

First, you will learn MySQL to understand how data is stored on the server, as well as how to write queries as efficiently as possible.

You can roughly imagine that server data is stored in a database management system called MySQL.

And to query data in MySQL, you need to learn how to write SQL statements.

Whether the server sends data to the interface quickly or slowly depends heavily on your SQL skills.

In addition, you can also write SQL statements to insert, delete, and update data.

Besides MySQL, there are other popular database management systems such as SQL Server, PostgreSQL, Oracle,… and all of them use SQL statements to work with data.

After retrieving data from MySQL, to ensure security, data should not be sent directly to the interface. Instead, it should pass through a Backend Framework.

There, the Backend Framework is responsible for handling business logic, user authentication, and data formatting to ensure data is safe and properly structured before being shown on the interface.

And the Backend Framework you will learn in this roadmap is ExpressJS, one of today’s most popular Backend Frameworks, built on NodeJS.

After finishing ExpressJS, you can move on to NestJS.

NestJS is a Framework built on ExpressJS. Therefore, once you master ExpressJS, learning NestJS becomes more convenient and easier.

However, if you don’t have much time, you can completely skip NestJS.

By this point, you have enough knowledge to build a complete system by yourself, from the Frontend interface to the Backend server infrastructure.

If your goal is to build your own product for personal work, you can stop here and start building immediately—don’t wait anymore!

On the other hand, if your goal is to learn in order to work at a company, then you must continue to the final part of this roadmap.

**Folder: Clip_09**

When your project has around 1,000 lines of code, things are usually still under control.

But when your project grows beyond 10,000 lines of code, everything becomes extremely complex.

If you don’t know how to organize source code properly, fixing bugs or adding new features will take a lot of time.

Even more dangerous is when you fix one place but accidentally create errors in many other places.

To solve this, Object-Oriented Programming, also known as OOP, is foundational knowledge you must master.

When applying OOP, your source code is no longer messy but packaged into independent modules.

This helps you easily reuse old code without spending time rewriting from scratch.

Thanks to this mindset of splitting projects into independent modules, **maintaining and upgrading** the system also becomes much safer and faster.

When something breaks, you only need to fix that exact place, minimizing the risk of fixing one part and accidentally causing errors elsewhere.

At the same time, adding new features also causes as few conflicts as possible.

Because of these advantages, OOP is always one of the top topics recruiters use in interviews to evaluate your capability.
